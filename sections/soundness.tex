\section{(Un)Soundness of Method Local Classes}
With our language primitives in place, we now consider type safety of two variants of our language.
The two variants differ only in the typing of local classes:
\begin{enumerate}
\item $\zeta(\mathsf{Java})$ types local classes with rule \textsc{new-local-java}, as Java does;
\item $\zeta(\mathsf{funnelled})$ types local classes with rule \textsc{new-local}.
\end{enumerate}
Both variants use the type test of Java:
rule \textsc{if-instanceof} accepts only checked casts, and at run time rules \textsc{ifThen} and \textsc{ifElse} compare class names only.
As shown in Section~\ref{sec:core}, $\zeta(\mathsf{Java})$ is unsound.
We now show that $\zeta(\mathsf{funnelled})$ is sound.

\begin{theorem}[Type Soundness]
Under a global $\decls$ such that $\mathsf{Dec}\gap\mathrm{Ok}$ for every $\mathsf{Dec}\in\decls$:
if $\typing{\emptyset}{\emptyset}{e_0}{T}$, and $e_0\rightarrow^* e$, then $\typing{\emptyset}{\emptyset}{e}{T}$ and either $e$ is of form $v$, or there is an $e'$ such that $\step{e}{e'}$.
\end{theorem}

The reduction is deterministic, up to the names chosen by $\mathsf{fresh}$.

\begin{theorem}[Determinism]
If $\step{e}{e_1}$ and $\step{e}{e_2}$, then $\mathsf{fresh}(e_1,e_2)$.
\end{theorem}
