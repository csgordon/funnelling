\section{Related Work}
\label{sec:related}
Generics / parametric polymorphism are known to have subtle and often unexpected interactions with other features,
as far back as work leading to the ML value restriction~\cite{wright1995simple,garrigue2004relaxing}.
The original design for Generic Java (GJ)~\cite{bracha1998making} enumerates a number of ways in which generics interacts with existing Java features, but does not discuss inner classes such as method-local classes (which first shipped around the time GJ was prototyped).

It is not uncommon to have ``intentional unsoundness'' in industrial languages,
such as Java's covariant array subtyping, TypeScript's covariant method subtyping, or pointer-integer conversions in C.
However these are intentionally designed into the language to improve ease of use, and in most cases (like Java's array handling)
problematic uses are detected at runtime and flagged with a specific exception (e.g., Java checks upon storing into an array that the new entry value
is a subtype of the array's original content type).
Less widely known is the ``sneaky throw'' hole in Java's checked exceptions, where
\begin{lstlisting}
@SuppressWarnings("unchecked")
public static <T, E extends Exception> T sneakyThrow(Exception e) throws E {
    throw (E) e;
}
\end{lstlisting}
allows throwing a checked exception as an unchecked exception by exploiting a simplification in bounds resolution.

\emph{Unintentional} unsoundness in industrial type systems is rarer, and typically arises from interactions of features that have not been carefully studied in combination
(as opposed to variants of core languages that add just one new feature at a time, when real languages have more).
The most notable example is Amin and Tate's discovery~\cite{amin2016java} that Java and Scala's handling of generic type constraints
was rendered unsound by the fact that \Q@null@ is treated as inhabiting all reference types, making all
type constraints (even nonsensical ones) satisfiable.
Servetto et al.~\cite{unsound_presentation} first pointed out the soundness issue with  publicly, though in the 
Q\&A session after the talk, multiple Java designers were unsurprised --- Gilad Bracha noted ``Once I saw the title of your talk, I understood what the problem was''
before explaining that these issues were well-known to the creators of \textsc{BETA}~\cite{kristensen2007and} (which lacks static type-checking, but actively views local declarations as tied to their enclosing dynamic context~\cite{kristensen1983abstraction} --- granularity 3 in \S\ref{sec:funnelling}'s taxonomy).
